# FinRadar (ФинПрогноз): прогноз денежных потоков и кассовых разрывов

Сервис для малого бизнеса: загружает банковскую выписку (CSV), строит прогноз остатка на 30 дней, находит дни возможного кассового разрыва и показывает сценарии «что если»: задержку оплаты крупным клиентом, падение выручки, внеплановый расход, отсрочку платежей поставщикам.

Стек: React + Vite + Tailwind (фронтенд), Node.js + Express (API), TypeScript-модель прогноза в `shared/`; Python + pandas/matplotlib для офлайн-EDA и графиков (`scripts/`, на сайте не выполняется).

## Локальный запуск

Сервис работает только локально (localhost), отдельный сервер не нужен. Нужен Node.js 24 (или 22.18+). Распакуйте проект в короткий путь, например `C:\projects\finprognoz`: на Windows длинные пути ломают сборку.

Режим разработки (горячая перезагрузка, без пароля):

```bash
npm ci
npm run dev
```

Production-сборка на локальном сервере (с паролем из `.env`):

```bash
cp .env.example .env        # задайте AUTH_USER и AUTH_PASSWORD
npm ci
npm run build
npm start
```

Сайт откроется на http://localhost:3000 (порт меняется через `PORT` в `.env`). Подробности и пересчёт офлайн-анализа на Python описаны в [SETUP.md](SETUP.md).

## Безопасность

- Все страницы и `/api/*` закрыты Basic-аутентификацией (`AUTH_USER` / `AUTH_PASSWORD`). Открыт только `/api/health`. В production без этих переменных сервер не стартует.
- Сервер не пишет в лог тела запросов и тексты ошибок: в логах остаются только тип ошибки и место в коде.
- Сырые выписки (`data/raw/`) не коммитятся и не раздаются как статика.

## Как показать жюри расчёт на контрольном датасете

1. **На сайте.** Загрузите CSV (с заголовком или без, одна или много компаний: формат как у `all_operations.csv`). Компания выбирается в строке статуса: на сайте её прогноз, предупреждения и сценарии «что если». Пошаговый журнал расчёта по каждой компании строит команда ниже.
2. **Одной командой — по всем компаниям сразу и с метриками:**

   ```bash
   npm run evaluate -- путь/к/контрольному.csv --open
   ```

   За несколько секунд в `reports/evaluate/<имя файла>/` появятся:
   - `report.html` — отчёт в одном файле (открывается без интернета): прогноз и статус каждой компании, её журнал расчёта и прогноз по дням, метрики, матрицы ошибок, графики, пошаговый журнал метрик; `--open` сразу открывает его в браузере;
   - `forecast_companies.csv`, `forecast_days.csv` — прогноз по компаниям и по дням (P10/P50/P90, доля сценариев ниже нуля);
   - `calc_log.md` — журнал расчёта прогноза каждой компании: чтение и очистка файла, сверка с остатком, статьи и регулярные платежи, выбор похожих периодов, сценарии, P10/P50/P90 по дням, предупреждения и правило статуса;
   - `backtest_metrics.json`, `backtest_cases.csv` (каждый прогноз против факта), `backtest_log.md` (каждая метрика по формуле с подставленными числами);
   - графики `1_…`–`9_…png`.

   Консоль печатает те же шаги: «Шаг 1/4. Прогноз…», «Шаг 2/4. Бэктест…», «Шаг 3/4. Графики», «Шаг 4/4. HTML-отчёт». Нужны Node.js и Python с matplotlib (`pip install matplotlib`); без Python отчёт собирается без графиков. Если в файле меньше 90 дней истории до среза и 30 дней факта после, прогноз и отчёт строятся, а метрики — нет (причина пишется в отчёт).

## Качество прогноза (бэктест)

Прогноз строится «из прошлого» на 6 датах среза (31.03, 30.04, 31.05, 30.06, 31.07, 31.08.2026) той же функцией, что на сайте, только по операциям до среза, и сравнивается с фактическим остатком следующих 30 дней (факт за 01.04–30.09.2026). Охвачено 137 компаний из 150 (у остальных меньше 90 дней истории или нет 30 дней факта), всего 793 прогноза.

**Прогноз остатка (медиана P50)**, ошибка = прогноз − факт по всем 23 790 точкам «прогноз × день»:

| Подход | MAE | MSE | RMSE | WAPE |
|---|---|---|---|---|
| Аналоговые периоды (текущая модель) | 1,17 млн ₽ | 1,06·10¹³ ₽² | 3,25 млн ₽ | 25,3% |
| Наивная: остаток не меняется | 1,23 млн ₽ | 1,14·10¹³ ₽² | 3,38 млн ₽ | 26,7% |
| Линейный тренд за 90 дней | 1,36 млн ₽ | 1,39·10¹³ ₽² | 3,72 млн ₽ | 29,6% |

Медиана P50 к 30-му дню на 30% возвращается к медианному остатку последних 60 дней: владельцы держат остаток около привычного уровня. Это снизило RMSE с 3,40 до 3,25 млн ₽ и WAPE с 26,3% до 25,3% (параметры выбраны на train.csv, проверены на test.csv). Точечный прогноз лишь немного лучше наивного (MAE на 5%, RMSE на 3,7%); крупные платежи — реальные и повторяющиеся, их сглаживание ухудшало прогноз. Сильная сторона — коридор: факт попадает между P10 и P90 в 76,9% точек при ожидаемых 80%.

**Обнаружение разрыва.** Разрыв — остаток на конец дня ниже 0 ₽ хотя бы в один из 30 дней. Считаются только прогнозы, сделанные до разрыва (32 прогноза с уже отрицательным остатком исключены): 761 прогноз, 10 новых разрывов (1,3%). Статусы сайта: от 10% вероятности (или P10 ниже нуля) — «Повышенный риск», от 50% (или P50 ниже нуля) — «Критический». Если за последний год остаток компании ни разу не уходил в минус, пороги 60% и 80%: такие компании держат резерв, и провал в сценариях у них почти не становится разрывом. Это правило сократило ложные тревоги с 282 до 75 при том же recall:

| Метрика | «Повышенный риск» и выше (≥ 10%) | «Критический» (≥ 50%) |
|---|---|---|
| Матрица ошибок (TP / FP / FN / TN) | 8 / 75 / 2 / 676 | 4 / 35 / 6 / 716 |
| Accuracy | 0,899 | 0,946 |
| Balanced accuracy | 0,850 | 0,677 |
| Precision | 0,096 | 0,103 |
| Recall | 0,800 | 0,400 |
| Specificity | 0,900 | 0,953 |
| F1 | 0,172 | 0,163 |
| Заблаговременность (медиана) | 21,5 дня | 21,5 дня |

Прогноз «разрыва не будет никогда» дал бы accuracy 0,987, не найдя ни одного разрыва, поэтому главное — recall, precision и F1. **Вероятность:** ROC-AUC 0,773 (модель правильно упорядочивает риск), average precision 0,041 при доле разрывов 0,013. Brier score 0,093 хуже постоянного прогноза «1,3%» (0,013): вероятность завышена — среди прогнозов с вероятностью от 50% разрыв случился в 5%. Модель ловит 8 из 10 разрывов в среднем за три недели; на один реальный разрыв приходится около 9 ложных тревог. Вероятность на сайте — доля исторических сценариев с минусом, ориентир для резерва, а не точная частота.


## Структура

| Путь | Что внутри |
|---|---|
| `server.ts` | Express API: анализ выписки, прогноз, аутентификация |
| `src/App.tsx` | Интерфейс: загрузка, выбор компании, прогноз, симулятор «что если» |
| `data/` | Демо-выписка C052 (её отдаёт сервер) и сводка EDA для слайдов `eda_summary.json` (сайт её не использует) |
| `data/raw/` | Сырые train/test кейса (локально, в git не входят) |
| `shared/statement.ts` | Чтение CSV (с заголовком и без, много компаний), очистка повторов, категории операций, журнал чтения файла |
| `shared/cashflow.ts` | Модель прогноза (аналоговые периоды), рекомендации, статус и пошаговый журнал расчёта; общая для сервера, интерфейса и скриптов (журнал расчёта пишут скрипты) |
| `scripts/` | Проверка файла одной командой (`evaluate.ts`): прогноз по компаниям (`forecast.ts`), бэктест и метрики (`backtest.ts`), графики (`plot_backtest.py`), HTML-отчёт (`report.ts`); EDA датасета (`run_eda.py`) и слайд EDA (`export_presentation_charts.py`) |
| `reports/` | Бэктест на train + test: метрики (`backtest_metrics.json`), каждый прогноз против факта (`backtest_cases.csv`), журнал расчёта метрик (`backtest_log.md`); результаты `npm run evaluate` — в `reports/evaluate/` |
| `docs/` | Текст кейса (`case.pdf`) и описание датасета (`dataset_README.md`) |
