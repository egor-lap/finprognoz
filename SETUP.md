# Инструкция по локальному запуску проекта

Данный проект содержит:
1. **Полнофункциональный веб-сервис (React + Vite + Tailwind CSS + Express Backend)** — загрузка выписки, прогноз остатка на 30 дней с вероятностью кассового разрыва, рекомендации и симулятор «Что, если?». Прогноз считается на сервере в момент загрузки.
2. **Python-скрипт EDA** (`scripts/run_eda.py`) — офлайн-анализ `all_operations.csv` (все операции кейса), сводка для слайда в `data/eda_summary.json`. Качество модели сайта измеряет бэктест `scripts/backtest.ts` (см. README).

Сервис запускается только локально (localhost), развёртывание на внешнем сервере не предусмотрено.

Структура данных:
- `data/*.json`, `data/demo_statement_c052.csv`: готовые артефакты, их читает только сервер (через `/api/*` после аутентификации).
- `data/raw/all_operations.csv`: сырые выписки кейса (все 150 компаний). Они **не коммитятся** (см. `.gitignore`). Положите их туда сами, если нужен пересчёт.

## Вариант 1. Запуск веб-сервиса

Сервису не нужны заранее рассчитанные данные: прогноз строится по загруженной выписке. Он готов к работе сразу после установки зависимостей Node.js.

В dev-режиме без `AUTH_USER`/`AUTH_PASSWORD` аутентификация отключена (в консоли будет предупреждение). В production (`NODE_ENV=production`) сервер без них не запустится.

### Требования:
- **Node.js** версии 24 (или 22.18+, нужен встроенный запуск .ts для `npm start`) ([скачать с официального сайта](https://nodejs.org/)). Vite 8 не поддерживает Node 18.
- **npm** (устанавливается вместе с Node.js).

### Шаги запуска:
1. Распакуйте скачанный архив и перейдите в папку проекта в терминале (PowerShell / Command Prompt / bash):
   ```bash
   cd путь_к_папке_проекта
   ```

2. Установите зависимости:
   ```bash
   npm ci
   ```

3. Запустите сервер разработки:
   ```bash
   npm run dev
   ```

4. Откройте в браузере:
   **[http://localhost:3000](http://localhost:3000)**

Приложение сразу готово к использованию!

### Production-режим на локальном сервере (с аутентификацией)

```bash
cp .env.example .env        # задайте AUTH_USER и AUTH_PASSWORD
npm run build
npm start
```

`npm start` раздаёт собранный `dist/` и требует логин и пароль из `.env`; без них сервер не запустится. Если порт 3000 занят, задайте в `.env` другой `PORT`. Проверка без пароля: `GET /api/health`.

## Вариант 2. Пересчёт EDA и графиков через Python

Если нужно заново посчитать сводку EDA по `all_operations.csv`, слайд EDA или графики бэктеста:

### Требования:
- **Python** версии 3.10 или 3.11 ([скачать с python.org](https://www.python.org/)).

### Шаги:
1. Создайте и активируйте виртуальное окружение (рекомендуется):
   - **Windows:**
     ```bash
     python -m venv venv
     venv\Scripts\activate
     ```
   - **macOS / Linux:**
     ```bash
     python3 -m venv venv
     source venv/bin/activate
     ```

2. Установите библиотеки:
   ```bash
   pip install pandas numpy matplotlib
   ```

3. Запустите скрипт EDA:
   - **Windows:**
     ```bash
     python scripts/run_eda.py
     ```
   - **macOS / Linux:**
     ```bash
     python3 scripts/run_eda.py
     ```

Скрипт прочитает `data/raw/all_operations.csv` (другой файл того же формата — аргументом: `python scripts/run_eda.py путь.csv`) и обновит `data/eda_summary.json`. Слайд EDA: `python scripts/export_presentation_charts.py`. Графики бэктеста — в README, раздел «Качество прогноза».

## Вариант 3. Контрольный датасет: прогноз, журнал расчёта и метрики

Нужны Node.js (как в варианте 1) и Python с matplotlib (как в варианте 2).

```bash
npm run evaluate -- путь/к/контрольному.csv --open
```

Команда строит прогноз по каждой компании файла ровно так же, как сайт, считает метрики бэктеста (Accuracy, Balanced accuracy, Precision, Recall, Specificity, F1, матрицы ошибок, MAE, MSE, RMSE, WAPE, ROC-AUC, Brier, калибровку, заблаговременность), рисует графики и собирает `reports/evaluate/<имя файла>/report.html`. Пошаговые журналы: `calc_log.md` (прогноз каждой компании) и `backtest_log.md` (каждая метрика с формулой и числами). На сайте тот же файл можно загрузить кнопкой загрузки: компания выбирается в строке статуса. Подробнее — в README, раздел «Как показать жюри».
